# Evaluation harness (AI-16)

The harness uses an immutable AI-04 release. For each `test` prompt it generates one answer
with the compiler-generated skill instructions and one without them, then grades both answers
against the skill's rubric. The `should_not_trigger` set is evaluated separately by AI-17.

## Run a benchmark

Compile the SkillSpec with BE-09 and save the target's instruction artifact (for example
`CLAUDE.md` or `AGENTS.md`). Then run:

```powershell
cd ai
.\.venv\Scripts\python.exe -m evaluation.harness run `
  --release .\evaluation\benchmarks\seed\releases\1.0.0 `
  --skill ai-engineer `
  --instructions C:\path\to\compiled\CLAUDE.md `
  --live
```

`--live` is required for real provider calls. The command reports its planned answer/judge call
count before making calls. Live runs require a reviewed skill record in the release, a configured
provider key, and a new output directory. Reports record the dataset name, version and
`dataset_sha256`, the compiled-instruction SHA-256, prompt versions, model roles, per-arm rubric
scores and LLM usage. Do not edit or replace an existing report directory.

For code-level smoke tests, inject a fake gateway in tests. Fake model output is not evaluation
evidence and cannot satisfy AI-16.

The machine-readable report and JSONL record contract, including statuses and error codes, is
defined in [AI-16 report contract](ai-16-report-contract.md) and
[its JSON Schema](../../evaluation/harness/report.schema.json).

## Calibrate the judge

Human labels are stored separately from the immutable benchmark because adding them is a later
minor dataset release. The harness accepts JSONL records with this shape:

```json
{
  "prompt_id": "ai-engineer/test-1",
  "prompt": "The exact benchmark prompt",
  "condition": "with_skill",
  "answer": "The exact answer reviewed by a person",
  "rubric_scores": {"ai-engineer/rubric-1": true},
  "reviewer": "reviewer-id"
}
```

Each record ties a review to an exact answer and includes one or more rubric decisions. The
prompt must match the pinned release, and rubric IDs must exist in that release. Run:

```powershell
.\.venv\Scripts\python.exe -m evaluation.harness calibrate `
  --release .\evaluation\benchmarks\seed\releases\1.0.0 `
  --skill ai-engineer `
  --labels .\human-labels.jsonl `
  --live
```

Agreement is calculated per rubric decision: each scored criterion for each labeled answer is one
decision, not one whole answer or benchmark sample. The 80% gate is raw exact agreement across
those individual decisions. Missing labels, failed judge calls, or raw agreement below 80% do not
pass. Calibration calls the judge on the exact human-reviewed answers; it does not regenerate
them.

The calibration report also includes Cohen's kappa as a chance-corrected statistic. It is
informational only and does not affect the 80% gate; it is `null` when expected chance agreement is
1 and the statistic is undefined. It is computed over successful judge decisions; failed calls
still make the calibration fail. Judge inputs contain the request, exact answer, and rubric only:
they do not include the `with_skill`/`without_skill` condition or the original skill instructions.

See [AI-16 human-labeling instructions](ai-16-human-labeling.md) before preparing labels.

## Model limitation

The answer and judge roles currently use the same configured model,
`openrouter/anthropic/claude-sonnet-5.5`. This can create self-preference and correlated errors.
Consider using a different model for judging in a later change; the current AI-16 gate does not
claim independence between the answer and judge models.

## Current limitation

The checked-in workspace contains the reviewed seed release `1.0.0`, but no live answer outputs or
human-label release. The release can be used to generate live benchmark answers; the AI-16
evaluation and calibration gates remain pending until those answers are generated and humans label
them. No labels should be inferred from fake runs or generated by an LLM.
